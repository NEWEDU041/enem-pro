📋 Capacity Planning Recommendations

Immediate Actions (0-1 week)

1. Optimize `/api/checkout` Endpoint (PRIMARY BOTTLENECK) Current P95: 2,860ms | Target: < 1,000ms
  • Implement Redis caching for customer data (30min TTL)
  • Add Stripe connection pooling (reduce cold starts)
  • Implement async payment processing with queue (Bull/RabbitMQ)
  • Add timeouts with graceful degradation
  • Consider webhook-based processing instead of synchronous
2. Optimize `/api/explicar` Endpoint (SECONDARY BOTTLENECK) Current P95: 1,226ms | Target: < 1,000ms
  • Cache explanations by question hash (Redis, 24h TTL)
  • Implement prompt optimization for faster inference
  • Add API timeout (8s) with fallback response
  • Pre-generate explanations for popular questions
  • Consider separate LLM service with autoscaling
3. Database Optimization
  • Create indexes: idx_user_id, idx_question_id
  • Enable connection pooling (min: 10, max: 50)
  • Add read replicas for reporting queries
  • Implement query caching

Short-term Actions (1-4 weeks)

1. Async Processing Architecture POST /api/checkout → Queue → Worker → Webhook Notification
2. Rate Limiting Implementation
  • Per-user limits: 10 requests/minute
  • Checkout queue: Max 50 concurrent (prevent stampede)
  • Use Redis for distributed rate limiting

Long-term Actions (1-3 months)

1. Horizontal Scaling
  • Deploy 3-5 instances behind load balancer
  • Use managed database (auto-scaling)
  • Implement service mesh (Istio)
  • Target: Handle 100+ concurrent users
2. Infrastructure Evolution
